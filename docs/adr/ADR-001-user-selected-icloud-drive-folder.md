# ADR-001: Пользовательская папка iCloud Drive для обмена

Статус: Superseded by [ADR-002](ADR-002-web-pwa-github-pages-supabase.md)  
Дата отмены: 2026-08-18  

Этот документ сохранён как история прежнего native iOS baseline. Решение больше не реализуется: Swift/iOS/macOS и iCloud transport удалены из проекта.

- Статус: принято
- Дата: 2026-08-17
- Решение принято: владельцем проекта

## Контекст

Первоначальный baseline предусматривал собственный iCloud Documents container, общий для iOS- и macOS-target. Такой контейнер требует iCloud capability, регистрации идентификаторов и членства в Apple Developer Program. Для MVP с одним Mac и одним iPhone необходимо передавать только версионированные Markdown/JSON-файлы, ZIP-пакеты и immutable progress events.

## Решение

В MVP используется обычная папка пользователя `iCloud Drive/ai-mentor`. Имя `ai-mentor` является каноническим для MVP. Приложение не создаёт и не использует собственный ubiquitous container.

- На iPhone пользователь один раз выбирает папку через системный document picker. Приложение сохраняет security-scoped bookmark и повторно запрашивает выбор, если bookmark устарел или доступ отозван.
- На Mac menu-bar helper просит выбрать ту же папку через системную панель и сохраняет security-scoped bookmark.
- Все файлы внутри папки считаются недоверенным вводом и проходят существующие проверки schema, размера, пути и SHA-256.
- Содержимое публикуется immutable-файлами; `published/latest.json` заменяется последним и служит commit pointer.
- Основной пользовательский путь синхронизации: при запуске приложения и вручную. `BGAppRefreshTask` остаётся best-effort оптимизацией.
- Собственные iCloud/CloudKit entitlements для MVP не используются.

## Последствия

Положительные:

- для транспорта файлов не требуется платная Apple Developer Program;
- папка и файлы видны пользователю в Finder и Files;
- не нужен backend, сервер или отдельная учётная запись;
- сохраняются пакетный протокол, идемпотентность и local-first модель.

Ограничения:

- пользователь должен выбрать папку на каждом устройстве хотя бы один раз;
- доступ может быть отозван, а bookmark — устареть;
- iCloud Drive может скачать файл с задержкой, поэтому точное ежедневное время не гарантируется;
- папку может изменить пользователь или другое приложение, поэтому доверять её содержимому нельзя;
- бесплатная Personal Team по-прежнему ограничивает срок подписи установленного native-приложения; это отдельный вопрос распространения, а не транспорта.

## Отклонённые варианты

- Собственный iCloud Documents container: избыточен для одного пользователя и требует платной developer capability.
- Локальный HTTP/Bonjour transport: не работает, когда Mac выключен или устройства находятся в разных сетях.
- Внешний backend/storage: добавляет авторизацию, эксплуатацию и новый threat model.
- Только ручной AirDrop: не обеспечивает приемлемый ежедневный цикл и обратную передачу прогресса.

## Проверка решения

Sprint 0 transport spike считается пройденным после демонстрации на физическом iPhone и Mac:

1. оба приложения выбирают папку `ai-mentor` в iCloud Drive;
2. Mac публикует валидный тестовый bundle и последним заменяет `latest.json`;
3. iPhone импортирует bundle и создаёт progress event;
4. Mac получает event, а повторная обработка не создаёт дубликат;
5. отзыв доступа, задержка загрузки и повреждённый файл дают диагностируемую ошибку без потери локальных данных.
