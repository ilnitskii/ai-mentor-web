# ADR-004: Версионированные релизы общего курса в Supabase

Статус: принято  
Дата: 2026-08-31

## Контекст

Baseline 2.0 поставлял общий Topic/Lesson/Card/Task только во frontend build. Это не позволяло опубликовать готовые недели независимо от deployment приложения и атомарно переключить учеников на проверенный snapshot.

## Решение

Канонический авторский источник остаётся в `content/`, а `apps/web/src/generated/course.json` остаётся offline fallback. Проверенный snapshot дополнительно публикуется в `public.course_releases`:

- stable `track_id` и монотонный `release_version` идентифицируют immutable релиз;
- полный snapshot хранится одним `jsonb`, чтобы связи lesson/card/task/week переключались атомарно;
- SHA-256 не позволяет повторно записать другое содержимое под существующей версией;
- для одного трека одновременно опубликован только один релиз, предыдущие архивируются;
- `anon` и `authenticated` читают только опубликованную строку; менять релизы может только `service_role` через ограниченный RPC;
- браузер проверяет `schema_version` и при ошибке сети или схемы использует собранный snapshot из IndexedDB/frontend.

## Последствия

Публикация контента теперь не требует пересборки Pages, но изменение формата требует новой schema version и совместимого клиента. Размер snapshot приемлем для 1–3 пользователей и четырёх недель; при существенном росте понадобится ETag/частичная загрузка. Миграции в `database/migrations/` остаются источником истины для схемы, YAML в `content/releases/` — для учебного содержания.
