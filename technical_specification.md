# Техническое задание: AI Mentor Web

Статус: baseline v2.0  
Дата: 2026-08-18  
Платформа MVP: responsive web/PWA на GitHub Pages  
Backend MVP: Supabase Free  
Основной домен: data analytics и подготовка к собеседованиям

## 1. Цель

Создать персональный учебный сайт для 1–3 пользователей, доступный на iPhone через браузер. Система должна помогать регулярно изучать темы, решать задачи, повторять материал и видеть доказательный прогресс. Раз в неделю Codex анализирует накопленные события, выявляет слабые места и публикует персональный отчёт, рекомендации и контрольную.

## 2. Границы MVP

В MVP входят:

- вход заранее созданных пользователей;
- ежедневный план, микроуроки, карточки и задачи;
- детерминированная проверка закрытых ответов;
- очередь свободных ответов на недельный review;
- XP, streak и mastery как разные показатели;
- offline‑чтение и локальная очередь событий;
- синхронизация с Supabase;
- недельный Codex report и контрольная;
- публикация frontend на GitHub Pages.

В MVP не входят:

- native iOS/macOS/Android приложения;
- App Store/TestFlight/iCloud Drive;
- публичная регистрация и коммерческий SaaS;
- выполнение пользовательского SQL/Python;
- платежи, команды и роли организаций;
- обязательная работа недельного pipeline при выключенном Mac;
- сложная админ‑панель.

## 3. Пользователи и доступ

- Владелец вручную создаёт 1–3 аккаунта.
- После bootstrap самостоятельная регистрация выключена.
- Каждый пользователь видит только свой прогресс, ответы, отчёты и задания.
- Общий учебный контент может быть публичным.
- Владелец pipeline может читать все учебные данные только для анализа и backup.

## 4. Основные сценарии

### A. Ежедневная сессия

1. Пользователь открывает сайт на iPhone.
2. Видит цель дня, ожидаемое время, серию и состояние sync.
3. Проходит микроурок, 5–10 карточек и одну задачу.
4. Детерминированные ответы проверяются немедленно.
5. Свободный ответ получает статус `pending_review`.
6. Действия сохраняются локально и синхронизируются с Supabase.

### B. Свободная практика

Пользователь выбирает тему или режим: повторение, блиц‑интервью, SQL/Python как текст, разбор ошибок. Результаты формируют те же progress events и влияют на mastery с ограничением антигринда.

### C. Offline/нестабильная сеть

1. PWA показывает ранее закэшированный контент и активную сессию.
2. Новые события сохраняются в IndexedDB outbox.
3. UI показывает количество ожидающих событий.
4. При восстановлении сети sync отправляет их идемпотентно.

### D. Недельный анализ

1. Scheduled task запускает pipeline на Mac.
2. Pipeline получает новые events и pending answers каждого пользователя.
3. Детерминированный aggregate считает evidence и слабые темы.
4. Codex получает только bounded summary, curriculum и нужный контент.
5. Candidate проходит schema/policy/diff validation.
6. Валидный report, reviews и контрольная транзакционно публикуются в Supabase.
7. Пользователь видит новый недельный отчёт при следующем открытии сайта.

### E. Сбой mentor-run

Cursor не сдвигается, предыдущий отчёт остаётся доступным, candidate попадает в локальный quarantine. Повторный run не создаёт дубликатов.

## 5. Функциональные требования

Приоритеты: P0 — обязательны для MVP, P1 — желательно после первого E2E, P2 — позднее.

### Auth/profile

- P0: email/password login для заранее созданных пользователей;
- P0: logout с очисткой локальных данных текущего пользователя;
- P0: цель, уровень, роль, язык, timezone и минут в день;
- P0: RLS‑изоляция данных пользователей;
- P1: смена пароля через owner‑controlled flow;
- P2: импорт резюме и вакансии.

### Сегодня

- P0: план, длительность и прогресс текущей сессии;
- P0: XP, streak, mastery summary и ближайшее повторение;
- P0: offline/sync status и pending event count;
- P0: продолжение незавершённой сессии;
- P1: краткое сообщение ментора с причиной выбора темы.

### Теория

- P0: sanitized Markdown, code blocks и таблицы;
- P0: микроурок 3–7 минут и контрольный вопрос;
- P0: ссылки на связанные карточки и задачи;
- P1: закладки и заметки;
- P2: изображения и CSV preview.

### Карточки

- P0: question/answer, multiple choice, true/false, SQL output prediction;
- P0: оценки «не помню / трудно / хорошо / легко»;
- P0: versioned scheduling reducer и очередь due cards;
- P0: объяснение после ответа;
- P1: cloze и short input.

### Задачи

- P0: choice, number, text и code-as-text;
- P0: условие, ограничения, hints, reference solution и rubric;
- P0: exact/normalized checker в браузере;
- P0: свободный ответ сохраняется как `pending_review`;
- P0: попытки, время и hints;
- P1: повторное решение ошибки;
- P2: отдельный безопасный remote runner.

### Прогресс

- P0: mastery по темам, accuracy, evidence count и история сессий;
- P0: журнал ошибок;
- P0: append-only events с уникальным `event_id`;
- P0: различать `completed`, `correct`, `mastered`, `reviewed`;
- P0: недельные отчёты и контрольные;
- P1: прогноз готовности к интервью.

### Sync

- P0: локальная запись до оптимистичного обновления UI;
- P0: автоматическая отправка при старте и событии `online`;
- P0: ручная кнопка retry;
- P0: idempotency по `event_id`;
- P0: конфликт payload с тем же ID отображается как ошибка, а не перезаписывается;
- P0: schema version validation для данных с сервера;
- P1: диагностический export без полных ответов.

### Недельный mentor-run

- P0: ручной CLI режим;
- P0: scheduled запуск один раз в неделю;
- P0: обработка каждого пользователя отдельно;
- P0: cursor по последнему успешно опубликованному диапазону;
- P0: bounded context без credentials/raw dumps;
- P0: schema и policy validation до записи в БД;
- P0: идемпотентная публикация report/assignment/reviews;
- P0: локальный backup перед изменением схемы или bulk publish;
- P1: ручное approve через candidate diff;
- P1: уведомление о результате run.

## 6. Учебная модель

### Сущности

| Сущность | Назначение |
|---|---|
| Track | цель и набор тем |
| Topic | узел карты навыков с prerequisites |
| Lesson | короткая теория и проверка понимания |
| Card | единица интервального повторения |
| Task | практическое задание и rubric |
| DailyPlan | порядок текущей сессии |
| ProgressEvent | неизменяемый факт действия |
| Review | результат проверки свободного ответа |
| WeeklyReport | факты недели, слабые темы и рекомендации |
| Assignment | контрольная, созданная по report |

Контент имеет стабильные namespaced IDs. Косметическое изменение не создаёт новый ID. Сущности с историей не удаляются, а архивируются.

### Mastery

Mastery — 0…100 и вычисляется versioned reducer из evidence:

- первая правильная попытка задачи имеет высокий вес;
- успешная карточка — средний;
- чтение — низкий и не поднимает mastery выше 40;
- hints и просмотр решения уменьшают вес;
- свежие независимые доказательства важнее старых;
- единичная ошибка не обнуляет тему;
- Codex объясняет evidence, но не назначает mastery напрямую.

### XP и streak

- XP отражает активность и не заменяет mastery.
- Одно событие не может начислить награду дважды.
- День засчитывается при минимум 10 XP и одном проверяемом ответе.
- После трёх выполненных дней выдаётся shield, максимум два.
- Допустимо одно мягкое возвращение в течение 48 часов.
- Простое повторение лёгких элементов имеет дневной cap.

## 7. Информационная архитектура

Основная навигация:

1. **Сегодня** — план и sync status.
2. **Учиться** — темы, уроки, карточки и задачи.
3. **Прогресс** — mastery, активность, ошибки и недельные отчёты.
4. **Настройки** — профиль, offline data, export и logout.

На ширине iPhone используется нижняя навигация; на desktop допускается sidebar. Все ключевые действия доступны одной рукой и не зависят от hover.

## 8. Нефункциональные требования

- Первый cached render на современном iPhone: целевой p95 до 2 секунд после первой загрузки.
- Основной daily flow остаётся работоспособным при временной потере сети.
- Любое действие записывается в IndexedDB до изменения UI.
- Production build работает по URL `https://<owner>.github.io/<repo>/`.
- Mobile layout поддерживается начиная с ширины 320 px.
- Поддерживаются keyboard navigation, screen readers, достаточный contrast и reduced motion.
- Все timestamps хранятся в UTC; учебный день вычисляется в timezone профиля.
- Логи не содержат passwords, tokens и полный текст свободных ответов.
- Клиент корректно обрабатывает 401, 403/RLS, 409/conflict, offline и unsupported schema.
- Для MVP достаточно последних актуальных Safari, Chrome и Firefox; iPhone Safari — release gate.

## 9. Приватность и безопасность

- Код frontend/backend schema публичен; пользовательские строки БД публичными не являются.
- Publishable Supabase key допустим во frontend только с RLS и least-privilege grants.
- Secret/service-role key, DB password и Codex tokens запрещены в frontend и git.
- Публичный signup выключен; accounts создаёт владелец.
- Реальные progress/answers не используются как fixtures.
- Markdown не исполняет raw HTML/JavaScript.
- Пользовательский код не выполняется автоматически.
- Backup хранится локально вне git.
- Перед первым mentor-run пользователь знает, какие учебные данные анализируются.

## 10. Метрики MVP

- полный цикл login → session → sync работает на физическом iPhone;
- ни одно подтверждённое событие не теряется при offline/retry тестах;
- Alice не может прочитать или изменить данные Bob в RLS tests;
- недельный повтор run не создаёт второй report;
- пользователь понимает слабую тему и evidence из отчёта;
- за четыре недели диагностический результат по выбранному треку улучшается;
- проект укладывается в бесплатные квоты при 1–3 пользователях.

## 11. Критерии приёмки MVP

1. GitHub Pages открывается на iPhone по домашнему и мобильному интернету в РФ.
2. Пользователь входит и видит только свои данные.
3. Сессия завершается online и при кратком offline с последующим sync.
4. Повторная отправка event идемпотентна; конфликт не перезаписывает данные.
5. Mastery/XP reducer покрыт unit tests.
6. Свободный ответ попадает в pending review.
7. Недельный pipeline создаёт report, review и контрольную.
8. Невалидный candidate не изменяет опубликованные данные и cursor.
9. RLS tests доказывают изоляцию двух пользователей и anonymous denial.
10. Локальный backup можно восстановить в отдельный test project.

## 12. Открытые решения Sprint 0

- конечное имя GitHub repository и Pages URL;
- доступность GitHub Pages/Supabase с конкретных ISP пользователя;
- Supabase region после измерения latency;
- итоговый IndexedDB wrapper;
- точная специализация первого трека и язык контента;
- требуется ли ручной approve каждого недельного candidate после первых трёх запусков.
